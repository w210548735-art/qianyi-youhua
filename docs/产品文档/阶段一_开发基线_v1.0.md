# 黔衣有话 · 第一阶段开发基线 v1.0

> 日期：2026-08-28
> 分支：`develop/phase-1`
> 状态：已完成开发与本地验收，待分支推送后进入 REVIEW

## 1. 阶段目标

交付一个可真实运行的基础闭环：

`画像采集 → 权威种子建库 → DeepSeek 素材/算法生成 → 本地中文向量化 → 混合检索 → 决策留痕 → 长短期 Agent 记忆`

第一阶段不实现内容发布、平台取数、反馈学习、路线收益、赚钱/亏钱报告。

## 2. 技术基线

- Python：Conda `DL`，Python 3.10.18
- API：FastAPI
- 页面：Jinja2 + 原生 JavaScript，只保证演示功能
- ORM/数据库：SQLAlchemy + SQLite，开启外键与 WAL
- 大模型：DeepSeek `deepseek-v4-flash`
- 向量模型：`BAAI/bge-small-zh-v1.5`，512 维
- 计算设备：CUDA/RTX 4060 优先，CPU 自动降级
- 向量检索：第一阶段使用 SQLite BLOB 持久化向量，Python/NumPy 余弦相似度扫描
- Git：私有仓库 `w210548735-art/qianyi-youhua`，阶段分支 `develop/phase-1`

## 3. 可信数据规则

1. 知识事实只允许来自用户明确确认、政府官网、UNESCO、国家级非遗名录等权威来源。
2. 模型生成的素材模板和平台策略标记为 `generated_template`，不得伪装为事实。
3. 未知店铺成本、收益和商单信息保持空值，不允许模型补造。
4. 每条 active 知识记忆必须同时存在来源和向量。
5. 密钥、数据库、模型权重、任务日志不进入 Git。

## 4. Agent 上下文规则

每次 Agent 调用固定组装：

1. 系统规则；
2. 当前任务压缩后的短期记忆；
3. 按当前 blogger 隔离检索出的相关 active 长期记忆；
4. 用户本轮输入。

禁止把全部历史记录无选择塞入提示词，禁止跨博主召回。

## 5. 长期记忆

统一使用 `memory_record` 与 `memory_embedding`，支持：

- `profile_fact`
- `user_preference`
- `verified_knowledge`
- `decision_summary`

状态包括 `candidate/active/rejected/superseded`。更新必须创建新版本并保留旧版本；模型猜测、失败结果和单次临时偏好不得自动成为 active。

## 6. 短期任务记忆

使用 `task_session/session_message/task_checkpoint/task_artifact`，同时维护：

`data/tasks/{task_id}/task.json、messages.jsonl、context.md、decisions.jsonl、checkpoints.json、artifacts/、final_summary.json`

数据库和文件共同用于中断恢复；任务结束生成长期记忆候选，但不自动激活。

## 11. 风险与第二阶段前置项

1. SQLite 向量扫描只适合当前演示规模，大规模数据需迁移向量数据库或 SQLite 向量扩展。
2. DeepSeek 外部依赖需要补充调用配额监控、退避重试和线上熔断。
3. 第一阶段没有认证授权；多用户或公网部署前必须增加身份认证和资源级权限。
4. Conda `DL` 环境有 Requests 依赖版本警告，当前不影响验收，但应在第二阶段前清理。
