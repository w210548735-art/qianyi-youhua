## 0. 一句话定位

给**贵州文旅博主 / KOC** 用的**个人内容中台**：把博主的创作经验变成可检索、可评估的数据资产，用 AI 建库、体检、产出内容与商单路线，再用真实数据反馈迭代，越用越懂博主。

## 1. 目标用户

| 角色 | 是谁 | 核心诉求 |
|---|---|---|
| 博主 / KOC | 贵州本地文旅创作者（非遗、美食、景区、民俗、山地农业方向） | 内容产出效率低、选题靠灵感、接不到匹配的商单、不知道观众要什么 |
| （间接）商单甲方 | 酒旅、非遗、餐饮、景区运营方 | 找到风格匹配、数据真实的对口博主 |

## 2. 名词解释

| 名词 | 含义 |
|---|---|
| 画像 | 一个博主的基本信息档案（风格、平台、内容等），系统对他的"认知底座" |
| 知识库 | 贵州文旅事实类资产：景点、非遗、美食、方言、典故，带可信度 |
| 素材库 | 创作类资产：选题、爆款开头、BGM、转场、拍摄手法 |
| 算法库 | 平台规律类资产：推荐机制、流量密码、标签体系、发布时间 |
| 体检 | 对知识库的评估：缺什么内容、可信度如何 |
| 产出 | 系统给博主的结果：脚本 / 分镜 / 路线推荐 |
| 路线推荐 | 结合博主画像，推荐探店打卡路线（含成本与收益），用于对接 KOC 商单 |
| 反馈 | 把真实数据（点击/评论等）回灌系统，让产出越来越贴合博主 |

## 3. 功能闭环（核心，不可拆分）

闭环共 **5 个环节**，环环相扣，最后一步写回画像后回到第二步，形成"越用越懂博主"的循环。

```
 ① 画像 ──→ ② 建库 ──→ ③ 体检 ──→ ④ 产出 ──→ ⑤ 反馈
  输入         生成         评估         推荐         回写
                                                 ↑__________|
                                        (回到 ②，画像已更新，产出更准)
```

| 环节 | 一句话职责 | 谁来做 |
|---|---|---|
| ① 画像 | 录入博主信息，形成画像档案 | 代码 |
| ② 建库 | 基于种子数据+画像，AI 生成知识/素材/算法三库条目 | AI + 代码 |
| ③ 体检 | AI 评估知识库：缺什么、可信度如何 | AI |
| ④ 产出 | a) 按风格生成脚本/分镜；b) 路线×画像契合度排序推荐 | AI + 代码 |
| ⑤ 反馈 | 录入真实指标 → 判定博主适合类型/踩雷点 → 写回画像 | AI + 代码 |

**闭环成立证据**：同一博主录入反馈前后，再次产出的结果**确实发生变化**。

## 4. 详细功能需求

### F1 画像录入（环节①）

**目标**：采集博主基础信息，作为全系统对博主的"认知底座"。

**功能点**：
- F1.1 表单输入以下字段（见 §5 数据字典 A）
- F1.2 支持创建、修改、查看、删除博主画像
- F1.3 画像中"适合的视频类型"字段由系统在反馈环节自动更新

**验收**：新建一个博主 → 可在列表看到 → 可改、可删。

### F2 自动建库（环节②）

**目标**：为博主生成内容资产库，供后续检索、体检、产出使用。

**功能点**：
- F2.1 一键"为当前博主建库"：系统基于【种子数据 + 博主画像】生成三库条目（初始 20-30 条）
- F2.2 三库共用一个"资产"概念，用"所属库"区分（知识/素材/算法），每库再分细分类别
- F2.3 每个资产条目带：来源、可信度评分（见 §5 数据字典 B）
- F2.4 资产的**增删改查**：新增、编辑、删除、按条件检索（按库/分类/标签/关键词）
- F2.5 建库可重复执行，不覆盖已有手工修改（新增合并，不删旧）

**验收**：点"建库"→ 三库各出现条目 → 能检索到"酸汤鱼/苗绣/黄果树"这类真实条目 → 能编辑和删除。

### F3 知识库体检（环节③）

**目标**：告诉博主"你的知识库缺什么、可信不可信"。

**功能点**：
- F3.1 一键体检：AI 扫描当前博主的知识库
- F3.2 输出：① 已有内容分类概览；② **缺失内容清单**（如"缺景区攻略类""缺方言典故类"）；③ **可信度评估**（哪些条目来源可靠、哪些标注存疑）
- F3.3 体检结果可查看、可留存（历史记录）

**验收**：对一个知识库只有美食条目的博主体检 → 明确提示"缺景区/非遗类"，并对"无来源标注"的条目给出可信度警示。

### F4 产出（环节④）

**目标**：给博主直接能用的内容结果，以及能接商单的路线推荐。

**功能点**：
- **F4.1 脚本生成**：输入主题（可选）→ 按博主风格 + 知识库 → 生成脚本（含分镜结构）。可多次生成、可换主题。
- **F4.2 路线推荐**：预置若干贵州路线（非遗/美食/山地/景区，每条带成本、收益、契合标签），与博主画像做契合度匹配，输出**排序后的推荐列表**，标注"适合你的探店打卡路线 / 可对接商单方向"。
- F4.3 每次产出存档（产出记录），供反馈环节关联。

**验收**：
- 非遗美食博主 → 能生成一篇"以非遗为切入点的探店脚本"
- 同一画像 → 路线列表按契合度排序，排前的是美食/非遗类，排后的是纯山地探险类

### F5 反馈闭环（环节⑤）

**目标**：用真实数据告诉博主"你适合做什么、踩了什么雷"，并让系统记住。

**功能点**：
- F5.1 对某条产出录入真实指标：播放/点击、点赞、评论、收藏/转发
- F5.2 系统基于指标 + 内容特征 → 输出分析：**博主适合的视频类型** / **踩雷点**
- F5.3 分析结果**写回该博主画像**（更新"适合的视频类型"字段）
- F5.4 画像更新后，再次建库 / 生成脚本时结果随之调整（闭环生效）

**验收**：录入"美食探店员 1 万播放 800 评论，纯风景 vlog 播放惨淡"→ 系统判定"适合美食+探店，风景类为雷区"→ 写回画像 → 再生成脚本，选题与风格明显偏向美食探店。

## 5. 数据需求（数据字典）

> 此处定义"系统需要存储哪些数据"。具体存储实现（数据库选型、表结构、索引、检索方案）在《技术方案》中评审确定，但**字段清单以本文档为准，开发不得随意增删**。

### A. 博主画像（blogger）

| 字段 | 说明 | 谁写入 |
|---|---|---|
| 博主名称 | 必填 | 用户 |
| 平台 | 抖音/小红书/B站/视频号 等 | 用户 |
| 内容风格 | vlog/口播/测评/剧情/科普 等 | 用户 |
| 创作内容类型 | 非遗/美食/景区/民俗/山地 等 | 用户 |
| 粉丝量级 | 数字 | 用户 |
| 更新频率 | 每周 N 条 | 用户 |
| 变现方式 | 带货/商单/知识付费 等 | 用户 |
| 常用路线/常去地点 | 文本 | 用户 |
| 适合的视频类型 | **系统生成**，反馈环节写回 | 系统 |

### B. 资产条目（asset，三库统一）

| 字段 | 说明 |
|---|---|
| 所属库 | 知识 / 素材 / 算法 |
| 分类 | 知识：非遗/美食/景区/方言/典故；素材：选题/爆款开头/BGM/转场/手法；算法：机制/流量/标签/时间 |
| 标题 | 条目名 |
| 内容 | 详细内容 |
| 标签 | 多标签，用于检索 |
| 来源 | 实锤 URL / 官方资料 / 自编 / 推断 |
| 可信度评分 | 0-5 分，AI 标注 |
| 创建时间 | 系统 |

### C. 产出记录（output）

| 字段 | 说明 |
|---|---|
| 所属博主 | 关联画像 |
| 类型 | 脚本 / 分镜 / 路线推荐 |
| 标题 | 产出标题 |
| 内容 | 正文 |
| 创建时间 | 系统 |

### D. 反馈指标（metric）

| 字段 | 说明 |
|---|---|
| 关联产出 | 关联某条产出记录 |
| 播放/点击量 | 真实录入 |
| 点赞数 | 真实录入 |
| 评论数 | 真实录入 |
| 收藏/转发 | 真实录入 |
| 记录时间 | 系统 |

### E. 路线（route）

| 字段 | 说明 |
|---|---|
| 路线名称 | 如"凯里酸汤鱼→西江苗寨" |
| 途经地点 | 文本 |
| 预估成本 | 数字 |
| 预估收益/商单价值 | 数字 |
| 契合标签 | 多标签，与画像匹配 |
| 适用博主类型 | 文本 |

### 检索要求
- 支持按"所属库 / 分类 / 标签 / 关键词"检索资产。
- 支持按博主查看其画像、产出、反馈。
- 检索速度不做苛刻要求，**结果准确、可理解即可**。

### 增删改查要求
- 画像、资产、产出、反馈、路线：均需**完整增删改查**。

## 6. 核心用户操作流程

**主流程（演示即此流程）**：
1. 进入系统 → 新建/选择一位博主，填写画像（F1）
2. 点【建库】→ 三库生成，浏览与检索（F2）
3. 点【体检】→ 看缺口与可信度（F3）
4. 点【生成脚本】→ 得到脚本（F4.1）；点【推荐路线】→ 得到排序后的商单路线（F4.2）
5. 对某条脚本【录入指标】→ 看分析结果（F5.2）
6. 再点【生成脚本】→ **结果已变化**（闭环证据）

**分支**：
- 博主信息变化 → 修改画像 → 后续产出随之变化
- 知识库条目可疑 → 体检标出 → 博主可编辑/删除该条目

## 7. 验收标准（演示闭环，45-60 秒）

| 步骤 | 演示动作 | 必须可见的结果 |
|---|---|---|
| 1 | 填一个"非遗美食博主"画像 | 画像入库，列表可见 |
| 2 | 点建库 | 知识/素材/算法三库出现 20-30 条，含真实贵州条目（酸汤鱼、苗绣、黄果树等） |
| 3 | 点体检 | 明确提示"缺景区/方言类"等缺口 + 可信度评分 |
| 4 | 生成脚本 | 一篇贴合"非遗美食"风格的脚本/分镜 |
| 5 | 推荐路线 | 美食/非遗路线排前，路线带成本与收益 |
| 6 | 录入真实指标 | 系统判定"适合美食+探店，风景类踩雷" |
| 7 | 再次生成脚本 | 结果与第 4 步明显不同，更偏美食探店 |

## 8. MVP 范围边界

**MVP 做**：
- 单博主（无需多用户/账号体系）
- 三库统一管理 + 增删改查 + 检索
- AI：建库生成、体检分析、脚本生成、反馈分析
- 路线推荐：预置路线 + 契合度算分
- 反馈闭环：真实指标手工录入，写回画像

**MVP 不做（后续迭代）**：
- AIGC 视频真实生成（MVP 用**脚本 + 分镜**合环）
- 平台真实数据自动对接（指标人工录入）
- 多用户 / 团队协作 / 权限
- 移动端
- 商单撮合交易（MVP 只做"推荐"，不做"交易"）
