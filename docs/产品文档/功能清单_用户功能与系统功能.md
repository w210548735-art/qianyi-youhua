# 功能清单 · 用户功能 vs 系统功能

> 版本 v0.1 · 2026-08-28
> 目的：把产品所有功能**分清楚**——哪些是**博主（用户）能点能用**的，哪些是**系统/Agent 自动运行**的。开发据此明确职责边界，产品据此演示"人机协作"。
> 依据：步骤一~四落地规格（输入建库 / 体检 / 产出规划发布 / 反馈报告）。

---

## 总览

```
┌───────────────────────────────────────────────────────────────┐
│                    博主（用户）能做的功能                        │
│  录入画像 · 建库 · 体检 · 生成脚本 · 排期 · 发布 · 看报告 · 改库   │
└──────────────────────────┬────────────────────────────────────┘
                           │ 用户动作触发
                           ▼
┌───────────────────────────────────────────────────────────────┐
│                    系统 / Agent 自动功能                       │
│  多轮对话采集 · 自动建库 · 自创指标 · 生成产出 · 提醒 · 定时回收   │
│  反馈分析 · 写回画像 · 更新店铺收益 · 更新指标 · 生成图表报告      │
└───────────────────────────────────────────────────────────────┘
```

## 一、博主（用户）能使用的功能

> 这些是**用户主动操作**的功能，前端有按钮/入口，评委能亲手点到。

| # | 功能 | 用户做什么 | 结果 | 对应环节 |
|---|---|---|---|---|
| U1 | **录入博主画像** | 回答 Agent 的多轮对话（平台/内容/风格/粉丝/变现） | 画像入库 blogger 表 | 步骤一 |
| U2 | **一键建库** | 点【建库】 | 三库+店铺库+指标体系自动生成 | 步骤一 |
| U3 | **浏览/检索库** | 按库/分类/标签/关键词/店铺搜，看条目 | 展示资产列表 | 步骤一 |
| U4 | **增删改查库** | 手动增/删/改/查资产、店铺、指标 | 库可被人工维护 | 步骤一 |
| U5 | **一键体检** | 点【体检】 | Agent 自创指标评估库 → 缺口/就绪功能 | 步骤二 |
| U6 | **生成脚本** | 点【生成脚本】（可指定主题） | 贴合风格的脚本/分镜 | 步骤三 |
| U7 | **推荐路线** | 点【推荐路线】 | 收益最大化排序的拍摄/KOC 路线 | 步骤三 |
| U8 | **内容排期** | 点【生成排期】 | 未来 N 天发布计划（哪天真什么） | 步骤三 |
| U9 | **一键发布** | 对某条排期点【发布】 | 内容发布到平台，状态变已发布 | 步骤三 |
| U10 | **手动录入指标** | 对某条产出录播放/点赞/评论/收藏 | 落 metric 表 | 步骤四 |
| U11 | **手动触发回收** | 点【回收数据】 | 立即从平台取数落 metric 表 | 步骤三/四 |
| U12 | **查看经营报告** | 点【生成报告】 | 图表报告：赚钱没/亏钱没/流量怎么样 | 步骤四 |

**用户功能的共性**：都是**主动触发**、有明确入口、可回退、可查看结果。

## 二、系统 / Agent 自动功能

> 这些是**系统后台自动运行**的功能，用户不操作也会发生，或由用户一个动作触发后自动完成。

| # | 功能 | 触发方式 | 自动做什么 | 对应环节 |
|---|---|---|---|---|
| S1 | **多轮对话采集** | U1 触发 | Agent 主动提问、追问、转换自然语言为结构化画像 | 步骤一 |
| S2 | **自动建库** | U2 触发 | 读画像+种子 → 生成三库条目+店铺库+指标体系 | 步骤一 |
| S3 | **自创指标体系** | U5 触发 | 读库分析关系逻辑 → 自创指标（名称/含义/评分逻辑/业务含义） | 步骤二 |
| S4 | **库体检评估** | U5 触发 | 按自创指标评估 → 缺口清单/就绪功能/健康度 | 步骤二 |
| S5 | **生成脚本/分镜** | U6 触发 | 综合画像+知识库+素材库+算法库生成 | 步骤三 |
| S6 | **收益最大化排路线** | U7 触发 | 读店铺收益属性 → 净收益/喜爱度/适合KOC排序 | 步骤三 |
| S7 | **生成内容排期** | U8 触发 | 读更新频率+已有产出 → 排未来 N 天 | 步骤三 |
| S8 | **执行提醒** | **定时自动** | 到 plan_date 且待发布 → 提醒博主"今天该发这个了" | 步骤三 |
| S9 | **定时自动回收反馈** | **定时自动** | 定时从平台取数（播放/点赞/评论/收藏）落 metric 表 | 步骤三/四 |
| S10 | **反馈分析** | U10/U11 触发 | 分析适合类型/踩雷点/资产有效性/店铺收益调整 | 步骤四 |
| S11 | **写回画像** | 反馈后自动 | 更新 blogger.suit_type | 步骤四 |
| S12 | **回写店铺收益** | 反馈后自动 | 更新 place.est_benefit（高数据上调/低数据下调） | 步骤四 |
| S13 | **更新指标体系数值** | 回收后自动 | 按 indicator.formula 取数更新 current/trend | 步骤四 |
| S14 | **生成图表报告** | U12 触发 | 读指标表 → 数据分析 → 折线图/柱状图 → 赚钱/亏钱结论 | 步骤四 |
| S15 | **决策可追溯** | 全程自动 | 每次决策写 decision_log（决定+理由） | 全程 |

**系统功能的共性**：Agent 自主决策、后台运行、定时触发或由用户动作联动触发、全部可追溯。

## 三、核心区别（一句话）

| 维度 | 用户功能 | 系统功能 |
|---|---|---|
| 谁操作 | 博主（人） | Agent（AI/后台） |
| 触发 | 主动点按钮 | 定时/联动/自动 |
| 特点 | 有入口、可回退、看得见 | 自主决策、后台跑、可追溯 |
| 示例 | 建库/生成/发布/看报告 | 采集/提醒/回收/分析/写回/报告 |

## 四、演示脚本（45-60 秒，展示用户功能+系统功能如何配合）

| 步骤 | 用户动作（用户功能） | 系统自动响应（系统功能） |
|---|---|---|
| 1 | 回答画像问题 | S1 多轮对话采集 → 画像入库 |
| 2 | 点【建库】 | S2 自动建三库+店铺+指标 |
| 3 | 点【体检】 | S3 自创指标 + S4 评估 → 显示缺口/就绪功能 |
| 4 | 点【生成脚本】 | S5 生成脚本 |
| 5 | 点【排期】→【发布】 | S7 排期 + 状态变已发布 |
| 6 | 点【回收数据】 | S9 自动取数落 metric + S13 更新指标 |
| 7 | 点【生成报告】 | S14 生成图表报告 → 显示"赚钱没/流量怎么样" |
| 8 | （可选）等提醒 | S8 定时提醒"今天该发这个了" |

**演示核心**：用户只做"点按钮"（U 功能），背后一切智能决策都是 Agent 自动完成（S 功能）——这就是"AI 赋能博主"。

## 五、MVP 实现边界

| 功能 | MVP 做 | 说明 |
|---|---|---|
| U1-U12 | ✅ 全做 | 用户功能是演示主体 |
| S1-S7 | ✅ 全做 | Agent 决策核心 |
| S8 提醒 | ✅ 做（前端展示"今日待发布"高亮） | MVP 用界面提醒，不做推送 |
| S9 自动回收 | ✅ 做（手动触发+定时逻辑演示） | MVP 模拟取数，演示"自动回收"流程 |
| S14 图表报告 | ✅ 做 | 折线图/柱状图，真数据 |
| 真实平台 API | ❌ 后做 | MVP 用模拟取数，演示闭环逻辑 |
